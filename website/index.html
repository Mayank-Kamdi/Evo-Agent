The Core Problem

Self-improvement needs more than a better score.

Existing self-improving agents mutate their execution harnesses using noisy, uncalibrated evaluation feedback. An apparent improvement on a random seed can mask severe regressions across other tasks.

1. Feedback Reliability

Evaluation signals may be incomplete (crashed episodes, missing rewards), highly variable across random environment seeds, or mismatched to the candidate code hash.

  • Is the evaluation evidence complete?
  • Are repeated outcomes statistically consistent?
  • Can reported outcomes be cryptographically verified?

2. Evolution Under Uncertainty

Standard self-improvement proceeds indiscriminately after every step. Without knowing whether evidence is trustworthy, evolution risk cannot be calibrated.

  • Should the system evolve now (ALLOW)?
  • Should it gather additional trials (REQUEST MORE)?
  • Should it defer harness modifications (DEFER)?

3. Regression Prevention

A candidate may discover a lucky heuristic that boosts one task while breaking 4 others. Without paired incumbent validation, harmful changes pollute the lineage.

  • Does the candidate genuinely outperform the incumbent?
  • Does it preserve previously successful capabilities?
  • Can harmful modifications be rolled back safely?
Foundation

Evo-Agent Foundation: Hierarchical Architecture

Evo-Agent operates across three layered scopes around a single frozen LLM backbone (DeepSeek-V4-Flash / GLM), separating code execution from harness evolution.

LEVEL 1

Task Harness Scope ($H$)

Executes agent steps on the target environment. Thinking is turned OFF at task time to cap per-step inference overhead. Interacts through a strict boundary seam: using_harness(agent, task).

harness.py prompts.py hooks.py context.py
LEVEL 2

Evolver Scope

Operates with thinking ON. Inspects execution traces, generates targeted edits, evaluates candidates with evaluate(), records ephemeral plans in plan.md, and squashes 2–5 diverse commits into the iteration pool.

evolve.py actions/ commit_iteration()
LEVEL 3 — META-EVOLVER SCOPE (Σ)

Outer Frozen Anchor & Strategy Rewriting

The meta-evolver's execution engine is frozen in godel_evolution_init/. It rewrites the strategy files in evolution/ (like select_seed.py and select_commit.py), preventing infinite self-modification loops while tuning the exploration policy.

select_seed.py select_commit.py strategies/ensemble.py submit_best.py
Crucial Invariant: Zero Backbone Model Weight Changes

Evo-Agent never trains, finetunes, or modifies the weights of the underlying LLM. Self-improvement is strictly confined to evolving the agent's Python code scaffolding and task harness.

Modular Implementation

Core Research Modules

Packaged into src/react_loop/reliability/ to guarantee strict backwards compatibility with original baseline runs.

MODULE A

Feedback Reliability Estimator

Estimates whether evaluation evidence $E_t$ is trustworthy enough to justify an evolution decision, decoupling signal reliability from raw score magnitude.

Signal Vector R(E)
  • Evidence Completeness: Ratio of completed vs requested episodes without harness exceptions.
  • Repeated-Run Consistency: Sample standard deviation $\sigma$ and Jackknife standard error.
  • Outcome Verification: Strict hash alignment between disk bytes and reported evaluations.
  • Historical Calibration: Brier score of past high-confidence evaluation predictions.
MODULE B

Confidence-Aware Controller

Evaluates the reliability score $R(E)$ against calibrated thresholds to govern whether the agent should evolve, request more data, or defer.

Discrete Decision Policy
  • ALLOW_EVOLUTION: Evidence meets completeness ($>0.95$) and variance constraints; agent proceeds to candidate modification.
  • REQUEST_MORE_EVIDENCE: High variance detected; dispatches supplementary episodes on existing seed before mutating code.
  • DEFER_EVOLUTION: Signal uncalibrated or harness crashed; preserves incumbent without state pollution.
MODULE C

Regression-Aware Validation

Guards candidate commitment in commit_iteration() via direct paired comparison against the incumbent on identical task seeds.

Validation Invariants
  • Paired Task Evaluation: Eliminates environment seed confounders by evaluating $H'$ and $H_0$ on identical task instances.
  • Regression Tolerance $\delta$: Rejects candidates that degrade performance on any previously solved sub-task beyond margin $\delta$.
  • Automated Rollback: Reverts disk state to $H_0$ if validation fails, recording failure rationale in BOOTSTRAP.md.
MODULE D

Adaptive Multi-Seed Rollouts

Dynamically scales evaluation sample depth $\kappa$ when high variance is detected, eliminating stochastic flukes before modifying harness code.

Statistical Invariants
  • Variance-Triggered Rollouts: Automatically provisions extra random seeds whenever trajectory variance $\sigma^2 > \tau_{var}$.
  • Jackknife Variance Estimation: Detects single-seed leverage outliers to avoid accepting lucky random walk breakthroughs.
  • Adaptive Token Allocation: Concentrates model thinking budget on ambiguous edge cases while fast-pathing consensus runs.
MODULE E

Automated Rollback Checkpointing

Zero-leak snapshot tree integrated into agent_evaluator.py and evolve.py, guaranteeing instant rollback on validation degradation.

Integrity Guarantees
  • Atomic Git Checkpointing: Every candidate mutation is tagged with an isolated Git commit ref prior to sandbox trial execution.
  • Fresh Import Invariance: Purges Python sys.modules caches during candidate reload to prevent phantom module leaks.
  • Zero-Residual Recovery: Restores harness disk state instantly upon regression trigger without manual intervention.
MODULE F

Failure-Attributed Knowledge Graph

Multi-factor failure taxonomy extending src/react_loop/knowledge_graph.py, ensuring the evolver never repeats disproven code modifications.

Causal Attribution Engine
  • Error Disentanglement: Distinguishes environment timeout, LLM context limits, and harness code syntax bugs.
  • Negative Feedback Synthesis: Injects structured historical counterexamples directly into get_iteration_begin_prompt().
  • Lineage Tracking: Preserves ancestor modification graphs across all meta-evolution cycles for auditability.

Protocol

Experimental Methodology

Rigorous benchmarking guidelines designed to ensure empirical reproducibility and eliminate evaluation data contamination.

BENCHMARKS

Evaluation Environments

Targeting standard game and text environments from the BALROG benchmark:

  • Primary: BALROG BabyAI (5 tasks): Goto, Pickup, Open, Putnext, PickUpSeqGoTo.
  • Secondary: TextWorld (3 game templates): Sequential object manipulation and navigation.
  • Sub-suite protocol: 80% dev exploration, 20% held-out test split (Setup B).
STATISTICS

Uncertainty & Significance

All reported numbers are subjected to rigorous variance isolation:

  • Lower Confidence Bound: $r = \mu - z \cdot \sigma / \sqrt{n}$ with $z=0.5$.
  • 5 independent repeated evaluation passes per test harness snapshot.
  • Paired t-tests for incumbent vs candidate comparisons ($p < 0.05$).
Research Hypothesis
“Estimating evaluation-feedback reliability and validating candidate harnesses against an incumbent can reduce harmful harness modifications while preserving the ability of hierarchical self-improving agents to improve task performance.”
Note: This is an empirical research hypothesis under active investigation, not an established scientific fact.

Limitations & Research Scope

Scientific boundaries and technical constraints governing this investigation.

⚠

Dependency on Evidence Quality

If the benchmark environment itself suffers from non-deterministic bugs or broken reward hooks, the reliability estimator may inherit these blind spots.

⚠

Backbone Capacity Ceiling

Evolving the harness cannot overcome fundamental reasoning failures of the frozen LLM. On environments exceeding model intellectual ceiling (e.g. NLE on DeepSeek-V4-Flash), no scaffolding can close the gap.

⚠

Computational Overhead

Paired validation against the incumbent and requesting supplementary evidence increases inference call counts by approximately 15–20% per iteration.

⚠

Empirical Calibration Requirement

Decision thresholds for the controller ($\tau_{\text{rel}}$) and regression gate ($\delta$) must be calibrated per domain; zero-shot universal thresholds may under- or over-constrain exploration.
